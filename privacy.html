Privacy policy

Life OS engine · updated 20 September 2026

The Life OS engine is a single-user personal tool run by Mason Lowe for his own data only. It has no other users and collects nothing from anyone else. This policy describes what the application accesses from his own Google Account and what happens to it.

Google data the app requests

  • .../auth/calendar.readonly — read-only access to Google Calendar. Used to see events, their times and their descriptions, so that commitments with real dates can be tracked and prepared for. The app never creates, edits or deletes calendar entries under this scope.
  • .../auth/gmail.readonly — read-only access to Gmail. Used to notice things that create a commitment: a deadline in a course announcement, an application closing, a reply that is owed. The app stores message headers (subject, sender, recipient, date, list id), labels and Gmail's own short snippet, and nothing else. It reads the text of each new email — at the moment it arrives, to decide whether it carries something the user has to do, and again when he asks about that email in the app's chat or through his own Claude connector. No message is skipped: anything that looks like a credential, a card number or a one-time code is removed from the copy sent to a model, and a message about signing in also has its links reduced to their web address. Message bodies are not stored: the text is read from Gmail when it is needed and kept nowhere. Under this scope the app never archives, deletes or modifies mail.
  • .../auth/gmail.send — send-only access to Gmail. Used for one thing: sending a message the user has asked for and approved himself — with a second tap on a card in the app, the Approve button under a draft in the app's chat, or his own approval in his Claude app when he uses his connector. The app never sends mail on its own, and nothing it reads can cause a send. This scope cannot read, archive, delete or modify mail.
  • .../auth/drive.file — access only to files the app itself creates in Google Drive. Used for one thing: a nightly backup copy of the app's own database, saved to a folder called "Life OS database copies" in the user's own Drive. It cannot see, open or change any other file in Drive. It keeps the newest 14 daily copies and the first copy of each month, and moves older copies to Drive's bin, which Google empties after 30 days. It also reads how much Google storage is free, so the user is warned before the account fills up.

Where the data goes

Into a private PostgreSQL database hosted on Railway, accessible only to the sole user. Other than the AI processing described below, it is not sold, rented, published, or shared with any third party, and it is not used for advertising or for any purpose other than showing that user his own next actions.

Each night a copy of that database is saved to the user's own Google Drive, as described above, so it survives if the host fails. The copy holds exactly the records this page describes the database holding, nothing more, and only the user can open it.

Content is sent to AI models so they can sort it and pull out what the user has to do: an email's sender, subject line and text, or a calendar event's title, time, location and the start of its description. Before anything is sent, the app removes from it, in its own code, anything that looks like a credential, a card number or a one-time code; a message about signing in also has its links reduced to their web address. One known automated error report is cut to its single error line, because its full text carries a live access token. Nothing else is withheld and no message is skipped. These requests pass through OpenRouter, a model gateway, with prompt logging turned off, and are answered only by providers on a fixed approved list: currently Microsoft Azure, OpenAI, Amazon Bedrock, Google, DeepInfra, Fireworks, Together, Parasail, CoreWeave and NextBit. Each is based in the US or the EU, and none may train AI models on this data; some keep requests for a limited period under their API terms. No provider based in China is used. No credentials are sent, and no message body is stored by this app — what a provider keeps under its own API terms is described above.

How long it is kept

  • Records of what was observed are kept as the app's long-term memory.
  • Message bodies are never stored. Short quotations — at most 200 characters, as evidence for something the app recorded — are kept with the record they explain.
  • Logs of model usage are kept for 12 months.

Limited Use

The app's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Withdrawing access

Access can be revoked at any time at myaccount.google.com/permissions, which immediately and permanently stops the app reading anything further.
